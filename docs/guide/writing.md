# 写作规范

本规范用于让不同投稿者提供的内容可以组合、检索和长期维护。投稿时在表单中选择内容归属和页面类型，其余目录、文件名与页面元信息由系统生成。

## 一、页面类型

| `type` | 用途 | 要求 |
| --- | --- | --- |
| `course` | 一门课程的长期主页 | 汇总页面定位、先修知识、学习目标、主要内容和资料链接 |
| `article` | 一个具体概念或问题 | 聚焦单一主题，并从课程页链接进入 |
| `index` | 学科或领域入口 | 由架构维护者管理范围、清单和推荐路径 |
| `guide` | 投稿与维护说明 | 由架构维护者记录操作规范 |

## 二、目录与命名

- 投稿者在表单中选择主要领域，系统据此确定二级目录。
- 每个页面只归入一个主要领域；跨领域关系通过标签、先修知识和站内链接表达。
- 已发布路径保持稳定。目录规则调整由架构维护者处理。

## 三、表单字段与页面元信息

投稿者填写的字段会转换为统一页面结构：

| 投稿字段 | 生成结果 |
| --- | --- |
| 目标领域 | 页面目录，以及学科和领域标签 |
| 页面类型 | `course` 或 `article` |
| 页面标题 | 页面标题和 `title` 元信息 |
| 页面简介 | `description` 元信息 |
| 内容属性 | `theory`、`experiment`、`methods` 或 `overview` 标签 |
| 署名 | `authors` 元信息；留空时使用提交者的 GitHub 用户名 |
| 先修知识 | `prerequisites` 元信息和正文中的先修知识列表 |
| 页面定位 | 页面定位章节 |
| 学习目标 | 学习目标列表 |
| 主要内容 | 主要内容章节 |
| 资料链接 | 资料链接章节中的统一表格 |
| 补充说明 | 可选的补充说明章节 |
| 媒体平台转发偏好 | `media_repost_preference` 元信息，用于原野象群自有媒体账号的运营安排 |

排序、发布状态、文件路径和页面格式均由系统填写。

### 标签的用法

标签用于描述页面的横向属性，帮助检索跨领域内容。投稿者不直接编写标签；系统根据“目标领域”和“内容属性”自动生成。

例如，归入“物理 / 光学”且内容属性为“实验”的页面，会获得 `物理`、`光学` 和 `experiment` 标签。页面仍只保存在光学目录中，不会在实验目录复制一份。

## 四、正文结构

1. **页面定位**：研究对象、适用读者、与相邻内容的边界。
2. **先修知识**：必须具备或建议具备的知识。
3. **学习目标**：完成后应能理解或完成什么。
4. **主要内容**：按知识关系组织主要主题。
5. **资料链接**：说明资料类型、大小、来源、授权和用途。
6. **补充说明**：按需记录常见问题、版本差异或维护信息。

资料链接和补充说明留空时，对应章节不会生成。

## 五、内容与资料要求

- 主要内容可使用 Markdown 标题、列表、公式、代码块和链接，不使用原始 HTML。
- 资料使用可公开访问的链接，并填写类型、大小、来源、授权和使用说明。
- 引用和资料说明应紧邻相关内容，并标明作者、来源、原始许可或使用依据。
- 不得把第三方内容当作自己的原创内容授权，也不得提交无授权转载内容或敏感信息。
- 学习目标应具体可验证，避免只写“了解”“熟悉”等无法判断的表述。
- 链接、术语和事实应在提交前核对。

## 六、发布要求

通过审核的投稿会被标记为 `published`。自动化流程会检查必填字段、页面格式、不安全内容和生产构建；检查失败时不会发布。
